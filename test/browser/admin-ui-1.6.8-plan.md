# 관리자 화면 1.6.8 시험 계획·실행 상태

기존 `node:test`·Playwright·시험 서버를 재사용한다. 제품 코드와 커밋은 이 시험 담당의 소유 범위가 아니다. 제품 시험은 통합 커밋 뒤 원격 자동 검사에서만 실행한다.

| 요구 | 진입·사례 | 독립 기대값·거부할 결함 | 수준 |
|---|---|---|---|
| 승인 대상 유지 | 같은 표시명의 서버 가·나 요청 상세에서 가만 승인 | 승인 전송 식별자가 가의 요청 하나이며 나의 요청은 대기 | 브라우저·요청 기록 |
| 비동기·상세 유지 | 실제 실행을 보류한 승인, 즉시 완료와 실패 | 승인 응답 202, 상세 식별 유지, 다음 요청 처리 가능, 실행 1회 | 실제 응용 통합·브라우저 |
| 응답 유실 | 승인 접수 뒤 응답 폐기, 조회 실패·대기·실행 순서 | 불명확 상태에서 추가 승인 전송 0, 읽기로만 해소 | 브라우저·요청 기록 |
| 접근·출력 | 키보드 상세 진입/닫기와 긴 출력 읽기 | 제목 초점·복귀 초점·출력 스크롤·원문 보존·출력 재실행 없음 | 브라우저 |
| 서버 초안 | 가·나 정책 편집과 원 작업 복귀 | 초안·검색 분리, 조회 대상 보존, 저장 전 적용 없음 | 기존 정책·다중 관리자 시험 |
| 시험 서버 표시 | 저장 정책과 편집 초안의 시험 서버 설정 | 실제 요청의 시험 상태를 초안 변경만으로 바꾸지 않음 | 정책·작업 브라우저 |
| 관리 범위 | 설정·중계기·표시 설정 이동 | 환경/재시작은 중계기에서만, 언어는 표시 설정에서만 | 브라우저 |
| 오래된 장부 | 생성 후 24시간을 넘은 실제 저장 기록을 이력에서 조회 | 요청 메모리에 없는 기록도 해당 날짜로 발견, 승인 전송 없음 | 실제 장부 통합·브라우저 |
| 작은 화면 | 320·820·1440 너비의 핵심 과업 | 가로 넘침 없음, 대상 식별과 상세 복귀·출력 조작 가능 | 브라우저·화면갈무리 |

기존 인증·명령/파일·모델 심사·출력·설치·언어·초안 계약 시험을 보존하고 승인 동작을 목록에서 상세로 이동한다. 내부 DOM의 `details.open` 기대는 선택 상세 유지라는 공개 행동으로 바꾼다. 날짜·검색·페이지는 새 서버 이력 조회 계약에 맞춘다. 모형 서버는 화면의 요청 전송·응답 수용을 확인하며, 실제 장부의 조회 정확성을 대신하지 않는다.

예정 명령은 기존 원격 실행기 `node test/browser/run.mjs all`이다. 기존 `UI_TEST_RESULTS`·`UI_SCREENSHOTS`를 재사용한다. 현재 제품 시험 결과와 회귀 실패/통과 증명은 모두 **NOT_RUN**이다. 로컬 실행 금지에 따라 잘못된 가져오기나 실행기 오류를 회귀 실패로 대체하지 않는다. 통합 커밋과 원격 영수증이 나오면 실제 시험 수·실패·건너뜀·종료 코드·화면갈무리를 기준으로 인계한다.
