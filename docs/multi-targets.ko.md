# 여러 SSH 대상 관리

한 중계기에서 같은 소유자가 관리하는 SSH 서버를 최대 32개 등록할 수 있습니다. 관리자는 보호된 환경 설정의 `BRIDGE_TARGETS`에 한 줄 JSON 배열을 넣고, 기존 SSH 설정에 각 대상의 읽기·쓰기 프로필을 준비합니다. 모델과 카드에는 등록 ID만 전달합니다.

```dotenv
BRIDGE_TARGETS=[{"id":"test","displayName":"시험 서버","readProfile":"test-read","writeProfile":"test-write","credentialRevision":"v1"},{"id":"prod","displayName":"운영 서버","readProfile":"prod-read","writeProfile":"prod-write","credentialRevision":"v1"}]
BRIDGE_DEFAULT_TARGET=test
```

각 프로필 쌍은 같은 host·port·user·인증 참조·경유 서버·`trustedHostKey`를 사용해야 합니다. 읽기 프로필은 `readOnly=true`, 쓰기 프로필은 `readOnly=false`로 설정합니다. 새 대상은 별도 경로에서 확인한 host key 지문을 두 프로필에 고정해야 하며, 서로 다른 대상이 같은 프로필·host/port·host key를 공유하면 시작을 거부합니다. 자격 자체는 SSH 설정과 기존 보호된 비밀 저장 경로에 둡니다. 키나 비밀번호를 교체하면 `credentialRevision`도 `v2`처럼 바꿉니다.

ID·프로필 이름·자격 revision은 영문 소문자로 시작하는 1~32자의 소문자·숫자·`_`·`-` 조합입니다. 표시 이름은 80 UTF-16 코드 단위까지 허용하며 제어·서식 문자를 거부합니다. `enabled:false`인 등록은 목록에 표시되지만 선택하거나 실행할 수 없습니다. 표시 이름은 공개 정보로 취급합니다.

`BRIDGE_TARGETS`와 `BRIDGE_DEFAULT_TARGET`을 모두 생략하면 기존 `aws-readonly`·`aws-local`을 `default`로 연결하며 기존 호출을 유지합니다. 배열만 설정하고 기본 대상을 생략하면 새 명령·전송 요청마다 `target`을 명시해야 합니다. 마지막으로 선택한 화면이나 최근 요청은 기본 대상이 되지 않습니다. 잘못된 대상과 비활성 대상은 거부하며 다른 서버로 대체하지 않습니다.

`list-targets`는 ID·표시 이름·활성 여부·고정 기본 대상만 반환합니다. `read-command`, `run-command`, `request-safe-command`, `request-upload`, `request-download`, `show-file-transfer`의 `target`으로 ID를 선택합니다. 이미 생성된 요청의 상태 조회·승인·거부·파일 저장은 요청 ID에 고정된 대상을 따릅니다. 관리자 웹의 대상 필터는 조회 범위만 바꾸며 승인 대상은 편집하지 않습니다. 파일 카드에서 대상을 바꾸면 이전 파일 선택과 진행 중인 화면 작업을 폐기하고 새 전송 카드를 받습니다.

대상 ID·설정 revision·실제 연결 대상은 요청과 결과에 남습니다. 승인·파일 전송 준비·artifact·다운로드 링크는 해당 대상에 결속되며 다른 대상의 티켓과 조합할 수 없습니다. 설정 변경에는 재시작이 필요합니다. 재시작 뒤 이전 준비 티켓과 메모리 내 요청·파일 ID는 다시 사용할 수 없습니다. 대상 프로필의 런타임 변경도 실행 전에 거부합니다.

대상별 원격 실행은 1개, 중계기 전체 원격 실행은 2개입니다. 일반 읽기와 자동 다운로드도 실행 한도에 포함됩니다. 외부 파일 가져오기는 전체 2개이며, 전송 파일당 최대 64 MiB와 기본 전체 staging 예산 512 MiB를 대상들이 함께 사용합니다. 서버 수만큼 예산을 늘리지 않습니다. 자리가 없으면 대기·자동 재시도 없이 거부합니다. 하나의 파일을 두 서버에 보내려면 각각 전송 요청과 승인을 만들어야 합니다.

유지보수는 전체 대상의 대기·실행·가져오기·미완성 파일이 정리된 뒤에만 예약할 수 있습니다. 종료 시 신규 접수를 막고 가져오기를 중단·정리한 뒤 시작된 읽기와 승인 작업이 끝날 때까지 기다립니다. 원격 부작용이 불명확하면 자동으로 다시 실행하지 않습니다. 기존 서버 업데이트·복원 절차와 owner 인증은 그대로 사용합니다.

한 중계기는 모든 대상의 자격과 디스크·감사 경로를 공유합니다. 대상별 요청 분리는 프로세스나 운영체제 수준의 보안 격리를 제공하지 않습니다. 서로 다른 관리 주체나 장애·침해 격리가 필요한 서버는 중계기를 별도로 설치해야 합니다. DB·다중 인스턴스 공유 큐·설정 hot reload·서버 간 직접 복사·일괄 승인은 지원하지 않습니다. Jev·모바일·ARM은 후속 단계입니다.

## 통합 관리자 화면

관리자 URL 하나에서 전체 대상의 대기·실행·실패 건수를 보고 서버 카드나 대상 선택 목록으로 요청을 좁혀 볼 수 있습니다. 건수는 메모리에 보관 중인 전체 요청 기준이며, 실패 건수는 보관된 실패 요청 수입니다. `등록됨`·`사용 중지`는 시작 시 설정 상태입니다. 화면을 갱신해도 SSH 연결을 시도하거나 서버 상태 점검 명령을 실행하지 않습니다.

실행 중인 요청은 별도 영역에 표시합니다. 종료 이력을 접어 둔 상태에서도 대상 이름과 ID를 볼 수 있으며, 각 목록은 요청 생성 시각의 최신 순서입니다. 승인·거부·파일 저장은 선택 필터가 아니라 요청 ID에 고정된 서버에 적용됩니다. 전체 대상에서도 요청을 하나씩 확인하고 승인합니다. 기존에 별도로 설치된 중계기를 자동으로 연결하지는 않으며, 같은 소유자의 대상 프로필을 한 중계기에 등록해야 합니다.

승인·이력의 `요청 조회 대상`과 설정의 `정책 편집 대상`은 서로 독립적입니다. 요청의 `이 서버 정책 열기`를 눌렀을 때만 해당 대상의 설정으로 이동합니다. 이름이 같아도 `[target ID]`로 구분하며, 다른 대상의 초안·검색은 이 페이지의 메모리에 유지합니다. 대상 이동 시 이전 검토·OK는 재사용하지 않습니다. 대기·실행 영역은 Tab으로 진입해 PageDown 등으로 스크롤할 수 있습니다. 상단 연결 표시는 관리자 HTTP 연결이며 SSH 접속 상태가 아닙니다.

`중계기 전체 환경설정 · ENV`와 재시작은 선택된 정책 서버 한 대에 한정되지 않습니다. 중계기에 등록한 모든 대상의 연결·요청에 영향을 줄 수 있습니다. 다중 대상 이름은 `BRIDGE_TARGETS`의 `displayName`으로 관리하며, `BRIDGE_TARGET_DISPLAY_NAME`은 기존 단일 대상 표시용입니다.

비활성·삭제된 대상 또는 설정 revision이 달라진 대상의 기존 정책은 현재 미적용으로 표시합니다. 다른 활성 대상의 정책을 저장할 때 수정하지 않은 규칙 전체는 그대로 보존합니다. 이 예외는 현재 DB의 전체 revision이 일치할 때만 인정하며, 변경·추가한 규칙은 현재 활성 대상과 revision·프로필이 일치해야 합니다. 미적용 정책 삭제도 체크한 초안을 검토·OK·저장해야 적용됩니다. 자동 삭제나 새 연결로의 자동 재결속은 하지 않습니다.

`enabled:false`는 일시 중지입니다. 같은 설정과 `credentialRevision`으로 다시 활성화하면 기존 revision과 정책이 다시 유효해질 수 있습니다. 권한을 폐기하려면 정책을 삭제하고, 자격 변경 시에는 `credentialRevision`을 올려 재시작합니다. 저장 출력의 `ready`는 저장·만료 상태이며 현재 읽기 권한을 보증하지 않습니다. 열 때 대상 활성화·revision·프로필·만료를 다시 검사하며 거부돼도 명령을 다시 실행하지 않습니다.

조회는 15초 제한을 두고 이전 조회를 취소할 수 있습니다. 일시적인 네트워크·서버 오류는 10초 주기로 읽기를 다시 시도하며 인증 거부 시 멈춥니다. 승인·정책 저장·ENV 저장·재시작은 자동 재시도하지 않습니다. 언어 적용은 처리 중이거나 저장 결과 확인이 필요한 동안 차단하고, 일반 미저장 초안은 폐기 확인을 받은 뒤 새로고침합니다. 정책·ENV·키 초안을 브라우저 저장소에 넣지 않습니다.
