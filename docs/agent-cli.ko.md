# 관리자 화면에서 CLI 설치

설정 화면의 **서버 CLI 설치**에서 등록 서버와 Codex·Claude를 선택하고 버전을 확인한다. 서버·공식 패키지·버전·계정 권한을 확인한 뒤 요청을 등록하고, 별도로 승인해 설치를 시작한다. 사용자 Jev 기준값과 자동심사 정책은 바뀌지 않는다.

브라우저에는 요청 키·ID와 서버·CLI 식별자만 임시 저장한다. 새로고침하면 기존 기록을 읽어 복원한다. 접수 응답이나 실행 응답이 끊기면 기존 요청 상태를 조회한다. 결과 불명은 서버 설치 기록으로 확인하며, 원래 실행 이력을 완료로 바꾸거나 자동으로 재설치하지 않는다. 브라우저 전송 계층의 같은 HTTP 요청 재전송에 대비해 서버에서도 요청 키와 작업 ID로 중복 실행을 막는다.

설치 완료는 로그인 완료를 뜻하지 않는다. 설치 대상의 SSH 계정으로 터미널을 열고 화면에 표시된 관리 설치 경로를 사용한다. Codex는 `login --device-auth`를 지원한다([공식 CLI 문서](https://learn.chatgpt.com/docs/cli/reference)). Claude는 실행 후 로그인 안내를 따른다. SSH에서 브라우저 콜백을 받지 못하면 인증코드를 터미널에 입력하는 흐름이 제공된다([공식 인증 문서](https://code.claude.com/docs/en/authentication)). 키나 코드를 관리자 웹 화면에 입력하지 않는다. 기존 외부 설치를 재사용하는 경우에는 그 실행 경로를 사용한다.

기존 외부 설치가 같은 버전이면 재사용하고, 다른 버전이면 별도 관리 경로에 설치한다. 원래 전역 실행 파일·로그인 파일·PATH는 바꾸지 않는다. 이후 웹의 업데이트는 관리 설치를 대상으로 한다. 완료 기록 저장에 실패하면 실패 기록을 먼저 저장한 뒤 이번 작업이 교체한 관리 링크만 복구한다. 실패 기록도 확정할 수 없으면 결과 불명으로 끝내고 검증된 새 버전의 활성화를 유지할 수 있다. 이때 이전 실행 가능한 버전·인증·사용자 파일은 보존하며, 이전 버전으로 복구됐다고 표시하지 않는다. 다른 작업이 링크를 바꿨다면 그 링크를 덮어쓰지 않고 복구 확인을 요구한다.

서버의 설치 기록 조회는 원래 요청의 결과 불명을 완료로 바꾸거나 재실행 권한으로 사용하지 않는다. 결과 불명 뒤에도 실제로 유지된 새 설치의 완료 기록을 관측할 수 있으며, 이후 정상 업데이트가 있었다면 이전 작업의 완료·재사용 기록은 당시의 이력으로 남는다.

공식 Codex·Claude 패키지의 고정 버전 설치·업데이트·외부 설치 공존은 격리 Linux에서 검증했다. 전체 기능 통합·독립 감사와 실제 TEST 설치는 남아 있다. 이 문서와 합성 브라우저 검사는 실제 서버 설치·로그인 완료의 근거가 아니다.

설치 파일 전송·npm·버전 확인에는 남은 계획 유효시간과 최대 900초 중 짧은 전체 시간 제한을 적용한다. 중단 중 살아 있는 이번 npm 프로세스 그룹만 종료·회수한다. 이 제한은 검증된 버전을 활성화하는 짧은 파일 교체 전에 해제하므로 복구 기록을 타이머로 중단하지 않는다. 설치 코드는 SSH 계정 권한으로 실행되며 별도 OS sandbox를 제공하지 않는다. 호스트 강제 종료·SIGKILL이나 외부 root 변경까지 정리를 보증하지 않으며 불명 결과는 조회로 확인하고 자동 재설치하지 않는다.

기존 CLI의 버전 조회 전에는 실행파일의 원래 경로와 심볼릭 링크가 가리키는 실제 경로의 파일·상위 디렉터리 소유권 및 쓰기 권한을 확인합니다. 다른 계정이 쓸 수 있거나 신뢰할 수 없는 소유자의 경로는 실행하지 않고 조회를 거절합니다. 기존 설치 파일의 권한이나 내용을 자동으로 바꾸지 않습니다. 같은 UID나 root의 악의적인 변경까지 격리하는 OS sandbox는 아닙니다.
