# 관리자 ENV 편집과 재시작

설정 페이지의 **서버 환경설정 · ENV**에서 현재 파일을 불러오고, 변경 내용을 확인한 뒤 **ENV 저장**을 누릅니다. 저장은 파일만 변경합니다. **서비스 재시작** 후 새 ENV가 적용됩니다. 저장하지 않은 초안은 재시작 전에 저장하거나 되돌려야 합니다.

| 구분 | 동작 |
| --- | --- |
| 편집 | 표시 이름, 카드 활성화·접두사, 업로드 도메인, 전송 크기·총량, 대상별 요청 보관 개수, 명령 자동승인 기능 활성화, Jev 활성화·호출 한도·시크릿 참조·API 키 |
| 비밀값 | 기존 키는 반환하지 않습니다. 빈 교체 입력은 보존하며, 설정 해제를 선택하면 해당 ENV 항목을 제거합니다. 직접 API 키가 있으면 시크릿 참조보다 우선합니다. |
| 터미널 전용 | 인증·토큰·Access 소유자·포트·SSH 대상·파일 경로. 화면에는 항목 이름만 표시합니다. |
| 백업 | `/var/lib/ssh-approval-env/backup-*.env`에 root 전용 0600으로 저장합니다. 처음 저장하기 전 ENV는 건강한 재시작까지 복구본으로 유지합니다. |
| 충돌 | 다른 관리자가 파일을 수정하면 저장·재시작을 거절합니다. 다시 불러온 뒤 변경해야 합니다. |
| 재시작 제한 | 실행 중·승인 대기·전송 중·유지보수 중에는 거절합니다. 승인 요청의 자동 승인과 별개의 관리자 작업입니다. |
| 확인·복구 | root 작업이 고정 서비스만 재시작하고 loopback health와 systemd 상태를 확인합니다. ENV 변경 후 기동 실패 시 이전 ENV로 복구하고 재시작합니다. 외부 Cloudflare 연결까지 보증하지 않습니다. |
| 결과 불명 | 저장·재시작 POST를 자동 재시도하지 않습니다. 상태만 조회합니다. 복구 실패 또는 연결 실패가 지속되면 서버 터미널에서 서비스와 ENV를 확인합니다. |

네이티브 설치를 업데이트한 뒤 서버 관리자 터미널에서 한 번 실행합니다.

`BRIDGE_REQUEST_CAPACITY`는 대상별 메모리 큐에 보관하는 요청 개수의 상한입니다. 기본값은 `100`이며 십진 정수 `100`~`1000`만 허용합니다. 필요한 TEST 환경에서만 상향합니다. 종료된 요청도 한 시간 동안 이 개수에 포함되며, 종료기록·출력의 보존 기간과 승인 정책, 대상별 단일 실행·전체 실행 슬롯 2개 제한은 바뀌지 않습니다. 저장 뒤 기존 보존 검사를 포함한 정상 재시작 절차로 적용합니다. 복구할 때는 `100`으로 되돌리거나 이 항목을 제거하고 같은 절차로 재시작합니다. 이미 보관된 기록을 삭제하거나 재실행하지 않습니다.

```bash
sudo bash /var/lib/ssh-mcp/app/approval-bridge/scripts/configure-env-editor.sh
```

이 도구는 전용 systemd socket과 root helper를 설치합니다. 웹 서비스의 사용자·sudo 권한·`NoNewPrivileges`는 변경하지 않습니다. helper는 `/etc/ssh-mcp-approval-bridge.env`와 `ssh-approval-bridge.service`만 다룹니다. 입력은 JSON으로 전달하며 셸로 실행하지 않습니다. API에는 기존 관리자 인증과 동일 Origin 검사를 적용하며 MCP에는 ENV 도구를 추가하지 않습니다.

Docker·Compose는 이 네이티브 연결을 사용하지 않습니다. 호스트에서 ENV를 수정하고 기존 Compose 업데이트 절차로 컨테이너를 재생성합니다. 외부 환경변수나 `BRIDGE_SECRET_ENV_FILE`로 설정을 덮어쓰는 사용자 구성도 터미널에서 관리합니다.

기능을 끄려면 서버 관리자 터미널에서 `sudo systemctl disable --now ssh-approval-env.socket`을 실행합니다. ENV와 root 백업은 보존됩니다. 재시작 예약은 별도 timer로 실행되므로 이미 접수된 예약의 취소를 뜻하지 않습니다.
