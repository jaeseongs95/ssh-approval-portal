# 1.8.0 배포와 데이터 이전

배포 계획을 고정하고 한 번 제출하면 별도 서비스가 준비·정지·이전·전환·검증을 수행합니다. 접수는 완료가 아닙니다. 작업의 `state`가 `PASS`여야 배포와 재시작 후 데이터 보존 검사가 끝난 상태입니다.

## 기존 서버 갱신

릴리스 파일은 root가 관리하는 디렉터리에 풀고, 별도로 확인한 `release-manifest.json`의 SHA256을 전달합니다. `/tmp`처럼 다른 사용자가 쓸 수 있는 부모 경로와 심볼릭 링크는 거부합니다. 아래 꺾쇠 부분은 실제 값으로 바꿉니다.

```bash
sudo python3 scripts/portal.py deploy plan --source /root/ssh-approval-portal-1.8.0 --manifest-sha256 <manifest_SHA256> --import-legacy
sudo python3 scripts/portal.py deploy apply --plan <planPath>
sudo python3 scripts/portal.py deploy status --job-id <jobId>
```

`--import-legacy`는 기존 1.7.0 설치를 명시적으로 이전할 때만 사용합니다. 이미 세대 방식으로 전환한 설치는 이 옵션을 빼고 같은 절차로 갱신합니다. 알려지지 않은 이전 버전·스키마·손상된 데이터는 추정해서 변환하지 않습니다.

계획에는 대상 호스트, 원래 서비스 기동 ID, 원본 세대, 릴리스와 실행기의 지문, 설정·키·인증 파일의 보호 지문을 고정합니다. 계획 뒤 대상이 바뀌면 실행을 거부합니다. 계획 파일은 서버의 root 전용 경로에 저장하며 다른 호스트에 복사해 실행하지 않습니다.

## 중단과 명시적 재개

먼저 같은 작업 번호로 `status`를 조회합니다. 작업이 실행 중이면 새 배포를 제출하지 않습니다. 중단된 작업을 명시적으로 재개할 때는 다음을 사용합니다.

```bash
sudo python3 scripts/portal.py deploy resume --job-id <jobId>
```

재개는 완료된 효과를 무조건 반복하는 명령이 아닙니다. 영수증과 실제 상태가 일치하면 다음 단계로 진행하고, 결과를 입증할 수 없으면 `NEEDS_REVIEW`로 남깁니다. 미확인 기동·데이터 이전·유지보수 해제를 자동 재전송하지 않습니다. 성공한 작업의 재개는 저장된 결과를 반환합니다.

`NEEDS_REVIEW`일 때 원본 데이터나 작업의 `owner` 파일을 삭제하지 마세요. 작업 폴더 `/var/lib/ssh-mcp/deployments/jobs/<jobId>`의 단계·오류 코드와 현재 서비스·활성 세대를 먼저 대조합니다. `owner`와 보호된 로그는 채팅이나 공개 릴리스에 올리지 않습니다.

## 데이터와 설정의 경계

- 코드는 `/var/lib/ssh-mcp/app/releases` 아래 불변 릴리스로 준비합니다.
- 네 SQLite 저장소와 출력 본문은 `/var/lib/ssh-mcp/data/generations/<jobId>/transfers`의 새 사본으로 이전합니다. 원본 세대는 덮어쓰지 않습니다.
- 활성 코드·데이터 선택은 `/var/lib/ssh-mcp/deployments/active.json` 한 파일로 게시합니다.
- 관리자 ENV는 `/etc/ssh-mcp-approval-bridge.env`가 계속 정본입니다. SSH 설정·키·CLI 인증 파일도 기존 경로에서 보존합니다. 배포 잠금과 ENV 도우미 잠금으로 전환 중 변경을 차단하고 전후 보호 지문을 대조합니다.
- 서비스 파일·도우미·실행기 교체는 별도 단계로 기록합니다. 여러 파일 교체 전체를 하나의 원자적 변경이라고 부르지 않습니다.

기존 SQLite가 가동 중 독점 잠금을 잡고 있으므로 정지 전에는 지원 릴리스·파일·공간을 검사하고, 정상 정지 후 데이터 변경 전에 실제 스키마와 본문을 판별합니다. 이때 미지원 형식이 발견되면 원본을 바꾸지 않고 검토 상태로 멈춥니다. 지원 여부 판별만으로도 중단 시간이 생길 수 있습니다.

기존 이력·정책·요청 식별자·출력 바이트·만료시각을 보존합니다. 구 형식 결과와 재시작으로 끝낼 미완료 요청은 명시적 이전 단계에서 변환하고 그 차이를 영수증에 기록합니다. 기동 중 구 데이터를 조용히 고치지 않습니다. 마지막 검증이 끝날 때까지 출력의 물리적 만료 정리를 보류하며 기존 만료시각은 연장하지 않습니다.

## 신규 설치

```bash
sudo python3 scripts/portal.py install --manifest-sha256 <manifest_SHA256> --admin-origin https://approve.example.com
```

이 명령은 계정·키·설정과 실행 환경을 준비한 뒤 빈 첫 세대의 배포 작업을 제출합니다. 출력된 작업 번호로 `deploy status`를 조회하세요. 기존 설치 흔적이 있으면 덮어쓰지 않고 거부합니다. `--grant-sudo-all`은 필요한 경우에만 명시하며, 지정하면 `mcpops` 계정 전체에 비밀번호 없는 전체 sudo 권한을 줍니다.

## 복구 제한

새 세대가 요청·인증 변경을 받은 뒤 이전 데이터베이스로 자동 복원하면 새 이력이나 토큰 폐기 사실을 잃을 수 있습니다. 따라서 자동 데이터베이스 복원과 구 `rollback` 경로를 제공하지 않습니다. 코드 문제가 생겨도 현재 데이터 세대를 보존하고, 데이터 계약을 확인한 수정 코드를 새 계획으로 배포하거나 보호된 작업 기록에 따라 수동 복구합니다.
