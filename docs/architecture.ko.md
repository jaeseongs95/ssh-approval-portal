# 구조와 호환성

[English](architecture.en.md) · [README](../README.ko.md)

이 문서는 0.3.0 구조 변경 후보의 책임 경계와 검증 기준을 설명합니다. 파일이 존재하거나 구조가 바뀌었다는 사실만으로 통합 시험·실제 클라이언트·배포 검증이 끝났다고 판정하지 않습니다.

## 세 계층과 조립 지점

| 위치 | 책임 | 경계 |
| --- | --- | --- |
| `src/domain/` | 승인 요청의 상태 전이·불변 조건·입력 검증 | filesystem·HTTP·환경변수·호스트 SDK에 의존하지 않습니다. |
| `src/application/` | 명령·파일·유지보수·종료의 사용 사례 | 주입된 큐·저장소·실행기·파일 공급자만 호출합니다. MCP 응답이나 HTTP 상태를 만들지 않습니다. |
| `src/adapters/` | MCP·HTTP·공개 응답·인증·설정·감사·저장·HTTPS source·SSH | 외부 표현과 내부 계약을 변환하며 I/O를 소유합니다. |
| `src/contracts/ports.mjs` | 중립 결과와 포트 계약·공통 한도 | `OperationOutcome`은 `{failed,texts,data?}`입니다. |
| `app.mjs`·`bridge.mjs` | 의존성 조립·자산 로딩·프로세스 기동 | 도메인 규칙이나 HTTP 라우트를 다시 구현하지 않습니다. |

내부 `Job.result`는 중립 결과를 사용합니다. 공개 presenter가 기존 `content`·`isError`·`structuredContent` 형태로 변환합니다. 기존에 주입하던 command callback 결과는 조립 지점에서 정규화합니다. SSH vendor의 내부 import는 `src/adapters/ssh/vendor.mjs`로 모읍니다.

## 보존할 동작

승인 전 원격 업로드 실행은 0회이고, 감사 저장과 사용자의 유효한 승인 뒤 실행은 한 번이어야 합니다. 만료나 감사 기록 실패가 실행 권한을 되살리면 안 됩니다. 즉시 읽기 실패도 terminal 감사 기록을 시도하고 내부 오류를 일반 응답에 그대로 내보내지 않습니다.

파일 저장소가 예약·완료·해제와 다운로드 완료를 소유합니다. 애플리케이션이 저장소 내부 상태를 직접 고치지 않습니다. 업로드의 파일명·크기·SHA-256·목적지·덮어쓰기·sudo 설정은 승인 요청에 고정합니다. 64 MiB 파일 한도, 기본 512 MiB 저장 총량, 10분 만료와 재시작 후 자동 재실행 금지는 유지합니다.

MCP 도구 이름·공개 Job 필드·오류 구분과 카드의 app-only 범위를 유지합니다. 승인·다운로드 자격은 기존 비공개 전달 경로에 두고 공개 결과 스키마에 넣지 않습니다. SDK가 받는 최상위 출력 스키마는 객체로 등록하고 실제 응답의 변형은 presenter에서 검증합니다. MCP의 실행 중 상태와 웹의 완료 대기 시점 차이는 기존 동작을 따릅니다.

관리자 인증은 기본 `token`입니다. `access` 모드의 소유자 로그인, 파일 다운로드 자격과 유지보수 토큰의 각 경계를 유지합니다. 설정 기본값과 허용 키는 `config/settings-contract.json`에서 관리하고 JavaScript·Python 소비자가 같은 origin·포트 검증 계약을 사용합니다. 두 포트의 기본값은 39124/39125이며 지원 범위는 1–65535입니다. origin 검증은 Node 24의 WHATWG URL 판정을 단일 기준으로 삼으며, Python의 `settings_contract.validate_origin`도 입력을 stdin으로만 전달해 `scripts/validate-origin.mjs`를 셸 없이 호출합니다.

카드의 파일 선택과 진행 상태는 해당 화면에 속합니다. 화면이 바뀐 뒤 이전 비동기 결과가 새 화면을 덮어쓰면 안 됩니다. 웹의 주기 갱신은 다른 요청의 포커스·선택·스크롤을 불필요하게 지우면 안 됩니다. 이 동작은 실제 브라우저에서 별도로 확인합니다.

## 변경과 검증

새 기능은 내부 중립 계약으로 구현하고 호스트별 파일 참조와 응답은 어댑터에서 처리합니다. Claude의 `file_uuid`나 빈 주소를 OpenAI 파일 입력으로 받아들이지 않습니다. 새 공급자는 실제 전달 계약과 네트워크 접근을 확인한 뒤 추가합니다. 현재 제한은 [에이전트 업로드 안내](agent-upload.ko.md)를 확인하세요.

소스 변경 뒤에는 해당 경계 시험을 실행하고 UI·웹 자산을 다시 빌드합니다. 전체 Node·Python·브라우저·Linux·네이티브·Docker·Compose 검증은 서로 다른 근거입니다. 비기본 포트의 유지보수·시작 검사·업데이트·복원, 기존 이미지 선택 보존, 원자적 시크릿 저장과 중첩 의존성 notice 목록도 확인합니다. 명령과 필수 검증은 [검증 계획](../test/PLAN.md)에 기록합니다.

실제 ChatGPT·Claude 승인 카드, 플랫폼 파일 입력, Google·GitHub·Cloudflare 로그인, 실제 ARM 하드웨어와 운영 배포는 각각 직접 수행한 기록이 필요합니다. 로컬 성공을 이 범위까지 확대하지 않습니다. 현재 작업은 로컬 변경·검증·기본 브랜치 병합 범위이며 공개 릴리스·원격 push·운영 배포는 별도 승인 대상입니다.
