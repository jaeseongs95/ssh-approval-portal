# 요청 접수 대기열

MCP 요청이 몰리면 인증 뒤, 도구 서버 생성과 본문 해석 전에 먼저 들어온 요청부터 처리합니다. 이 대기열은 기존 SSH 실행 제한이나 관리자 승인 이력을 대신하지 않습니다. 대기했다는 사실은 실행 승인이 아닙니다.

| 경로 | 일반 처리 중 | 접수 대기 | 최대 접수 대기 시간 | 분리된 긴 응답 |
| --- | ---: | ---: | ---: | ---: |
| MCP | 8 | 32 | 5초 | 64 |
| 관리자 | 4 | 16 | 5초 | 8 |

위 값은 보수적인 초기 상한입니다. 전체 프로세스의 메모리나 처리량을 보장하는 수치는 아닙니다. MCP 본문의 기존 1MiB 제한과 SSH 실행·파일 전송·승인 이력의 기존 제한도 계속 적용됩니다. 미완성 HTTP 본문은 30초, 헤더는 15초의 수신 시간제한을 적용합니다. 이 시간은 SSH 명령 실행 제한이 아닙니다.

일반 처리 중 자리가 남지 않으면 유한한 대기열에 넣습니다. 대기열이 차면 `REQUEST_QUEUE_FULL`, 시작 전에 5초가 지나면 `REQUEST_QUEUE_TIMEOUT`, 종료 중이면 `REQUEST_QUEUE_CLOSED`로 거부합니다. HTTP 상태는 `503`, `Retry-After`는 `1`이며 응답의 `executionAttempted:false`와 `requestSubmitted:false`는 해당 요청의 처리를 시작하지 않았다는 뜻입니다. 서버가 이 요청을 나중에 자동 실행하지 않습니다.

인증과 도구 입력 검증을 통과한 `wait-for-request`는 별도의 유한한 긴 응답 자리를 사용합니다. 긴 대기 호출이 일반 도구 호출을 전부 막지 않습니다. 이 자리가 차면 MCP 오류 `REQUEST_WAIT_LIMIT`로 응답하며 승인 대기 구독도 만들지 않습니다. 관리자 동기 승인 응답도 별도 자리를 사용하므로 승인 결과를 기다리는 동안 상태 조회·거부·유지보수 요청이 일반 자리를 쓸 수 있습니다. 관리자와 MCP의 자리는 서로 독립적이고 `/health`는 대기열 밖에서 응답합니다.

시작 전 연결 종료·대기 시간초과·서비스 종료는 대기 항목을 제거합니다. 이미 시작한 SSH 작업은 연결이 끊겼다는 이유만으로 취소됐다고 간주하거나 다시 실행하지 않습니다. 승인 요청이 이미 등록됐다면 기존 요청 번호로 상태를 확인해야 합니다. 대기열은 메모리에만 있으며 재시작 후 실행을 재생하지 않습니다.

`/health`의 `requestAdmission.mcp`와 `requestAdmission.admin`은 각각 `active`, `queued`, `detached`, `closed`와 설정된 상한을 보여줍니다. 명령·본문·인증정보는 포함하지 않습니다. 실제 서버 장애 원인과 부하 한계는 별도 관측으로 판단해야 합니다.
