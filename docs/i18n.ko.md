# 관리자 화면과 카드의 다국어 처리

국제화를 판정하는 단일한 `i18n 규격`은 없다. 이 제품에서는 언어 식별에 [BCP 47 / RFC 5646](https://www.rfc-editor.org/rfc/rfc5646.html), JavaScript 지역 형식에 [ECMA-402](https://tc39.es/ecma402/), 문서 언어 표시에 [HTML의 lang 속성](https://html.spec.whatwg.org/multipage/dom.html#the-lang-and-xml:lang-attributes)을 적용한다. 메시지 키·폴백 순서·자리표시자 문법은 아래의 제품 계약이다. ICU MessageFormat 같은 별도 메시지 형식의 준수를 주장하지 않는다.

관리자 화면과 승인 카드는 `web/src/locale.js`의 공통 처리와 기존 한국어 메시지 키를 사용한다. 한국어 원문을 키로 쓴 사실만으로 번역 결함으로 판정하지 않는다. `web/src/i18n.js`, `web/src/ui-text.js`, `ui/src/i18n.js`, 실행 한도 패널의 `web/src/capacity.js`가 실제 한국어·영어 카탈로그를 제공한다. 정책·명령·출력·사용자 입력은 번역 대상으로 바꾸지 않는다.

`Intl.getCanonicalLocales`로 Unicode BCP 47 locale identifier를 정규화한다. ECMA-402가 받는 이 집합은 BCP 47 전체와 같지 않다. 예를 들어 사적 사용 태그 `x-foo`는 BCP 47에서는 유효하지만 `Intl`에서는 거절된다. 구현은 거절된 값·빈 값에 `en-US`를 사용하며 IANA 등록 여부 전체를 검증하지 않는다. `ko` 계열은 한국어 메시지, 그 밖의 언어는 영어 메시지를 사용한다. 지역 없는 `ko`·`en`은 각각 `ko-KR`·`en-US`를 사용한다. `fr-FR`처럼 메시지 카탈로그가 없는 태그도 숫자·날짜에는 해당 지역 선호를 전달한다. 실제 지원 지역·달력·숫자 체계는 엔진의 `Intl` 데이터에 따라 결정된다.

문서의 `lang`은 실제 메시지 언어인 `ko` 또는 `en`이다. 형식 지역인 `locale`과 구분한다. 관리자 화면은 선택한 i18n 객체를 한도·측정값·서버 CLI·명령 편집·데스크톱 패널에 전달한다. 따라서 영어 메시지를 표시하는 `de-DE` 선호도 독일 지역 숫자·날짜를 유지한다. 브라우저별 저장 언어 선택과 기존 페이지 이동·초안 보존 흐름은 유지한다.

숫자와 날짜는 `Intl.NumberFormat`과 `Intl.DateTimeFormat`으로 표시한다. 시간대는 기기의 현지 시간대이며 숫자 입력·정책 저장값은 지역 중립적인 값을 유지한다. 실행 한도·명령 목록 개수는 `{queued}`, `{running}`, `{count}` 같은 이름 있는 자리표시자가 포함된 문장 전체를 번역한다. 명령 이름 추가 안내의 영어는 `Added command names to the draft: {count}.`처럼 개수와 무관한 문장을 사용한다. 현재 지원하는 한국어·영어 문장을 위해 복수형 라이브러리를 추가하지 않는다. 향후 수에 따라 형태가 달라지는 새 문장을 넣는다면 메시지 언어의 복수 규칙에 맞는 변형과 0·1·여러 개 사례를 함께 추가해야 한다. 형식 지역이 프랑스어여도 영어 폴백 메시지의 복수 규칙은 영어다.

카탈로그를 만들 때 양쪽 언어의 키, 메시지 문법, 자리표시자 일치를 검사한다. 문법은 `{name}`이며 이름은 영문자로 시작하고 영문자·숫자·밑줄을 허용한다. 값은 한 번만 치환하며 HTML로 해석하지 않는다. 값이 빠진 자리표시자는 그대로 남긴다. 조회는 카탈로그 자신의 키만 사용한다. 알 수 없는 키는 영어 카탈로그를 거친 뒤 보간 없이 원문을 반환하므로 `constructor`, `__proto__` 같은 이름도 상속 속성으로 오인하지 않는다. UI 카탈로그를 명령·출력·서버 경로·사용자 문맥의 번역기로 사용하지 않는다.

전역 실행 대기·동시 실행 한도는 중계기 화면에서, 선택 서버의 한도는 서버 화면에서 편집한다. 서버의 빈 입력은 API에 `null`을 보내 전역값을 상속한다. 적용된 실효 한도와 마지막 조회 시점의 대기·실행 현황을 함께 표시한다. 설치 기본값은 가용 CPU 수의 10배와 CPU 수이며, 한도 축소는 실행 중인 작업을 강제 종료하지 않는다. 저장은 리비전을 포함한 POST 한 번으로 보내며, 응답을 잃으면 다시 저장하기 전에 GET으로 실제 값을 확인해야 한다. 초안은 페이지 메모리에만 남는다.

서버 데스크톱 뷰어는 별도 `web/src/desktop.js`에 있다. 선택 서버의 현재 revision을 확인한 뒤 실제 OS 화면 연결을 요청하며, PNG 화면과 프레임·좌표계·입력 순번·요청 키를 함께 유지한다. CSS 표시 크기와 물리 화면 크기의 비율로 좌표를 변환하고 기기 픽셀 비율을 다시 곱하지 않는다. 키와 클릭은 누른 뒤 해제하는 한 묶음으로 전달한다. 입력 응답을 잃으면 자동으로 재입력하지 않고 화면을 다시 관측한다. 기본 뷰어는 클릭·단축키·텍스트 전송을 지원하며 드래그는 지원하지 않는다. Tab 키는 브라우저 초점 이동을 보존한다. 연결이 열려 있으면 서버 선택과 언어 새로고침을 잠그며, 다른 페이지로 이동하거나 앱에서 로그아웃할 때 연결 닫기를 요청한다. 서버 계정 로그아웃은 하지 않는다.

검증 명령은 `node --test test/i18n.test.mjs test/capacity-ui.test.mjs test/capacity-ui-desktop.test.mjs test/command-line-import.test.mjs`다. 카탈로그 키·자리표시자·문법·언어 폴백·지역 형식, 실제 번역 호출의 누락, 상속 키 오류·미등록 원문 보존, 패널별 형식 지역 전달, 명령 추가의 0·1·여러 개 메시지를 검사한다. 브라우저 통합 회귀는 `node --test test/browser/history-language.test.mjs test/browser/command-line-import.test.mjs test/browser/agent-cli.test.mjs`로 언어 새로고침·원문 보존·명령 편집·CLI 흐름을 확인한다. 제품 시험은 승인된 테스트 서버 또는 CI에서 실행한다. 이 문서는 시험 통과를 주장하지 않으며 실제 실행 결과는 해당 실행 근거로 판단한다.
