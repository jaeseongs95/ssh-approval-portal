# 승인 완료 agent 알림

> 이 문서는 1.x의 계약과 검증 기록입니다. 2.0.0에서는 [공개 MCP 도구 계약](mcp-tools.ko.md), [에이전트 연결](agent-clients.ko.md), [PC 파일 전송 클라이언트](client-files.ko.md)를 사용하세요. 아래의 예전 도구 이름과 한도를 2.0.0 호출에 적용하지 마세요.

승인 카드나 포털 요청을 안내한 agent는 사용자에게 채팅으로 승인 완료를 다시 알려 달라고 요청하는 대신 `wait-for-request`를 호출합니다. 서버는 원래 요청의 상태 변경 callback으로 대기 중인 호출에 응답합니다. 별도 웹훅 주소나 agent·벤더별 설정은 받지 않습니다.

```json
{"id":"원래 요청의 48자리 ID","until":"approval","timeoutMs":25000}
```

`until: approval`은 실제 승인 후 실행 중이 되거나 거부·만료 등 종료 상태에 도달하면 응답합니다. `until: completion`은 실행 종료를 기다립니다. 이미 결정된 요청은 즉시 반환합니다. 반환된 `callback.approved`는 승인 사실이며 실행 성공이 아닙니다. 실행 성공은 `callback.executionSucceeded`, `state`, `auditError`를 함께 확인합니다. 알림에는 기존 상태와 비밀을 제거한 저장 출력 참조만 포함됩니다. 명령 출력 본문은 `read-command-output`으로 명시적으로 읽습니다.

기본 대기는 25초, 최대 60초이며 대상별 동시 대기는 64개로 제한합니다. `callback.event: timeout`은 승인·실패 결정이 아닙니다. 같은 요청 ID로 대기를 이어가고 요청이나 SSH 명령을 다시 제출하지 않습니다. 서버 재시작 뒤 `missing`·`expired`·`unknown`도 재실행 근거가 아닙니다. 대기 취소는 명령 실행 취소나 승인 취소가 아닙니다.

알림은 진행 중인 MCP 호출의 응답으로 전달됩니다. agent가 대기 호출을 하지 않고 턴을 종료했거나 연결이 끊어진 경우 임의로 agent를 깨우지는 않습니다. HTTP 연결 종료와 서버 종료는 대기를 해제합니다. stateless MCP에서 별도 취소 알림만 보내는 클라이언트는 원래 대기가 기한까지 남을 수 있으나 제한 시간 뒤 회수됩니다. 기존 승인 정책·감사·실행 claim·만료·재시도 금지 규칙은 그대로 적용됩니다.
